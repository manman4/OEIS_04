# A400464：異なる2要素の積が全て異なる集合の最大サイズ

[400464_01.py](400464_01.py) は、Erdős Problem 425のF(n)を厳密に求め、各項が確定するたびに `b400464.txt` を更新する。対応範囲は1..100、既定の最後の添字は100。

2026-10-27の高速化で、既定の探索を問題専用の分枝限定法へ変更した。標準ライブラリだけで動作し、Z3は既定の計算には不要。実装は積の衝突条件から独立に作成したもので、外部プログラムのソースは転載していない。

## 実行

カレントディレクトリをこのファイルのある `400/400464/` とする。61までの計算はユーザーが実行する。

```bash
python3 -B 400464_01.py 61
```

既存の `.venv` を使う場合も、同じ引数で実行できる。

```bash
.venv/bin/python -B 400464_01.py 61
```

既存checkpointの達成集合と上限を再確認し、その次から再開する。ファイル名・引数・checkpoint形式は旧版と互換である。`--checkpoint`、`--bfile`、`--output` で保存先を変更できる。

- `b400464.txt`：確定済みの全項を `n a(n)` の2列で保存する。
- `problem425_checkpoint.json`：確定値、達成集合、各項の処理時間・探索ノード数を保存する。
- `terms_1_to_N.txt`：指定したNまで完成したときに、1行の項の一覧を保存する。

標準出力は完成した項の一覧、進捗は標準エラーへ出す。結果は一時ファイルからの置換で保存する。途中で止まっても、確定していない値を項として追加しない。Ctrl+Cまたは `--timeout-ms` による打ち切りの後は、最後に確定した項の次から再計算する。探索中の木の途中までは保存しない。

同じ出力先への並列書き込みは `.lock` を使って拒否する。空のロック用ファイルは残るが、OSのロックはプロセス終了時に解放される。ロック取得中のファイルを手動で削除しない。

## 高速化の要点

[アルゴリズムと枝刈りの証明](ALGORITHM.md)に条件・上限・正当性を記す。

1. 等しい積を作る4要素を、禁止集合として前計算する。
2. 選択済みの要素から残り2要素の両立関係を更新し、グラフの彩色から追加可能数の上限を得る。
3. 再証明済みの前項までの最大値を、候補全体の上限に使う。OEIS掲載値やb-fileは上限の入力に使わない。
4. 大きい素数とその2倍からなる組の対称性を整理し、同じ内容の探索を減らす。

## 検査と計測の範囲

[test_400464.py](test_400464.py) では、小さいnの全探索、対称性を加えた後も最大値を達成できること、彩色上限、保存・再開・中断・書き込み失敗を確認する。検査用の出力は一時フォルダーに置く。

```bash
.venv/bin/python -B test_400464.py
```

旧Z3方式は `--engine z3` で比較用に残した。これだけは[requirements.txt](requirements.txt)のZ3を必要とする。Z3が入っている場合、上記テストで30まで両方式を照合する。Z3を入れていなければ、この比較だけをスキップし、他の検査は実行できる。

[試作版の計測](performance_20261027.json)では、同じ専用探索により1..61を最初から計算して約27.24秒だった。既存の1..51の保存値とも一致した。これは保存処理を統合する前の試作の実測であり、完成版の61までの実行時間や、100までの所要時間を保証するものではない。

既存のcheckpoint・b-fileを61まで更新する本番実行は、この高速版の作成作業では行っていない。ユーザーが実行する。
