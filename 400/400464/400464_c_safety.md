# A400464のC版：探索の根拠と保存・再開

対象は[400464_01.c](400464_01.c)。1からnまでの整数の部分集合について、相異なる2要素の積が全て異なるものの最大サイズを求める。1も選べる。全ての部分集合積を比較するA401472とは条件が異なる。

## 実行

このファイルのある `400/400464/` をカレントディレクトリとする。macOS・Linuxのファイル操作と `flock` を使う。

```bash
cc -O2 -std=c17 -Wall -Wextra -Wpedantic -Werror 400464_01.c -o 400464_01
./400464_01 --help
./400464_01 64
```

対応範囲はN = 1..1000、既定値は60。この上限は添字と整数演算を保証する範囲であり、1000までの探索が実用的な時間で終わるという意味ではない。再実行時は保存済みの値も1から再計算するため、大きい範囲では検証にも時間がかかる。

出力先はカレントディレクトリの `b400464_01.txt`。Python版の `b400464.txt`、チェックポイント、項の一覧には触れない。ソースを更新した後は、実行ファイルも再コンパイルする。

## 数学的な根拠

選択済みの集合Aの相異なる2要素の積を `used` に記録する。新しい正整数xを加えたときに増える積は、Aの各要素aに対するa*xである。xは正なので、これらの積どうしは異なる。従って、既存の積に含まれるものが一つもないことが、追加可能であるための必要十分条件になる。

新しく記録した積は既存の積と重ならないため、再帰から戻るときにその積だけを消せば、元の `used` に戻る。

[隣接項と素数での増分の証明](400464_prime_step_proof.md)より、次が成り立つ。

```math
a(n-1)\le a(n)\le a(n-1)+1.
```

増分がある場合、サイズa(n-1)+1の解には必ずnが含まれる。よって、nを含む解の有無を調べれば次の値が決まる。残りの候補が1からxまでなら、その中から選べる個数はa(x)以下なので、この値による枝刈りも正しい。

「自由な素数」pは、選択済みの要素にpの倍数がない場合だけ使う。後で選ぶ整数はp未満なので、最終的な集合でpの倍数はp自身だけとなる。pを含む積と含まない積は衝突せず、pを含む積どうしの一致も相手の整数が等しい場合に限られる。従って、pは必ず選んでよく、積を記録せず個数だけを数えてよい。省略済みの自由な素数も同じ性質を持つので、この処理を重ねても判定は変わらない。

探索で使う `fval` には、その実行中に既に証明した値だけを格納する。保存ファイルの値は別配列へ読み込み、比較対象としてのみ使う。

## 添字・整数・メモリの範囲

- Nの文字列全体を検査し、1..1000の整数と確認してから前計算する。`int` が少なくとも32ビット相当の範囲を持つことをコンパイル時に確認する。
- 1からNまでの相異なる2数の積は高々N*(N-1)。`used` は(N+1)*(N+1)バイトなので、全ての積が有効な添字に収まる。N = 1000でも積は999000以下、確保量は1002001バイトである。サイズの乗算は、計算前に `SIZE_MAX` で検査する。
- `A`、`fval`、`spf`、`cntp` は全て長さ1001。候補、選択要素、素因数の添字は0..1000以内である。`spf` は候補全体について初期化してから使い、素因数での除算では値が必ず減少する。
- 選択個数k、自由な素数の個数fr、各素数の使用個数は高々N。選択個数k+frは目標に達した時点で止める。目標も高々Nであり、枝刈りの和k+fr+a(x)は高々2*Nである。
- 素数判定のq*qは高々1024、ふるいの次のjは高々2000。配列を走査した後のループ変数も高々1001であり、全て要求した整数範囲に収まる。
- 再帰ごとに候補xが減るため、深さは高々N段。通常の十分なスタックを持つ実行環境を前提とする。メモリ確保に失敗した場合は既存結果を書き換えず終了する。

これらの境界は、再証明済みの前項だけを使うことを前提とする。未検証の保存値を代入してこの範囲を壊す経路は設けていない。

## 保存と再開

- 読込み前に `b400464_01.txt.lock` で排他を取得する。この安定したロックファイルは終了時に削除しない。ファイルが残っているだけでは実行中を意味しない。
- 保存行は、連続した添字、1..nの値、隣接項の増分、行数、改行、余分な文字まで検査する。不正・不完全な行を見つけた場合は停止し、自動的な切捨てや修復は行わない。
- 指定したNまで定義から再計算し、保存値と照合する。既存の範囲を延長する場合は、全ての既存値を再検証してから新しい項を保存する。Nが保存範囲より小さい場合はNまでだけ検証し、後の行もそのまま保持する。後の行の最大性まで検証したとは扱わない。
- 新しい確定項ごとに、証明済みの接頭辞全体を `mkstemp` による固有の一時ファイルへ書く。書込み・フラッシュ・ファイル同期・クローズを確認してから、原子的に置き換える。以前の固定名 `b400464_01.txt.tmp` は使わない。
- 置換前の書込み・同期・置換の失敗では、元の結果を残してエラー終了する。保存できた新しい項だけを標準出力へ出し、進捗と診断は標準エラーへ出す。保存後に標準出力が失敗した場合も、結果ファイルは残る。
- プロセス中断時にも結果ファイルは新旧いずれかの完全な接頭辞になる。残った固有の一時ファイルは再開資料として使わず、Git管理から除外する。
- 結果とロックについて、シンボリックリンク、複数のハードリンク、通常ファイル以外への操作を拒否する。

排他が有効なのは同じロック規約に従うプログラム間である。ロックを無視する旧実行ファイルや外部編集との同時書込みは保証しない。また、親ディレクトリを同期していないため、停電・ストレージ故障時のディレクトリエントリーの永続化は保証範囲に含めない。

## 検証

[回帰検査](test_400464_c.py)は、実行ファイル・結果・故障を注入するファイルを全て一時ディレクトリへ置く。

```bash
python3 -B test_400464_c.py
```

1を含む場合も含めて集合を直接列挙し、相異なる2要素の実際の積を比較する独立実装でn = 1..12を検算する。再開、小さいNでの保持、不正な保存値・引数、行数の境界、ロック競合、リンクやFIFOの拒否、読込不能、書込み・同期・置換・メモリ確保の失敗、置換直前の中断も検査する。

N = 1000では表と素因数の初期化、最大の積の添字を確認する。CLIの1000も、意図的に誤らせた保存値をn = 2で検出する条件で確認する。これはa(1000)を計算する検査ではない。

警告付きコンパイル、静的解析、サニタイザーは上の数学的な根拠や境界の議論を補う検査であり、それだけをもって全ての実行条件での安全性を保証するものではない。

2026-10-27の確認では、通常の回帰検査13件と、UBSan・整数サニタイザーを有効にした同じ13件が通った。警告をエラー扱いにしたコンパイルとClang静的解析も通った。ASan付きのビルドは成功したが、直前の監査で実行環境のランタイム初期化に失敗しており、ASanの動的検査は完了していない。a(64)やa(1000)までの完全探索は行っていない。
