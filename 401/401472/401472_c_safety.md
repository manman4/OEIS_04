# A401472のC版：計算範囲、再開と保存の保証

対象は[401472_01.c](401472_01.c)。定義は、1からnまでの整数の部分集合で、空集合を含む全ての部分集合積が相異なるものの最大サイズである。1は選べない。既存プログラムの数学的な探索を保ち、入力・再開・保存処理を独立に修正した。

## 使用方法

このファイルのある `401/401472/` をカレントディレクトリとする。POSIXのファイル操作と `flock` が利用できるmacOS・Linuxを対象とする。

```bash
cc -O2 -std=c17 -Wall -Wextra -Wpedantic -Werror 401472_01.c -o 401472_01
./401472_01 --help
```

計算時は、実行ファイルに最後の添字を指定する。対応範囲は1..64、既定値は30。必要な表の上限は `MAXHB` で指定し、既定値は26、設定できる範囲は10..30とする。表が上限を超える場合やメモリ確保に失敗した場合は、未確定の値を保存せずエラー終了する。64までの終了時間は保証しない。

## 数学的な不変条件

相異なる正整数の積の一致は、全ての素数について指数の和が一致することと同値である。部分集合の指数の和は、各素数pについて $`v_p(N!)`$ 以下なので、それを表せる幅を各成分へ割り当てれば、成分間の桁上がりは起きない。Nが64のときも幅の合計は42ビットである。

既に選んだ集合の部分集合積の指数ベクトルをPとすると、新しい要素xを加えられる条件は次である。

```math
(P+v(x))\cap P=\varnothing.
```

平行移動は単射なので、新しくできる積どうしが衝突することはなく、上の条件が既存の積との衝突をちょうど除外する。

[隣接項と素数における増分の証明](401472_prime_step_proof.md)より、次の項は前項か前項に1を加えた値になる。増分がある場合は必ずnを含む。また、残りの候補がx以下なら、追加できる個数は再証明済みのa(x)以下である。

自由な素数pは、選択済みの要素にも今後選ぶ要素にも、p以外のpの倍数がない場合だけ使う。その指数はpを含むかどうかを単独で識別するため、pは必ず選べる。pの指数が0の層と1の層では以後の判定が同じになり、表を倍増させず個数だけを数えてよい。

## 添字と算術の範囲

- Nは文字列全体を検査し、1..64の整数と確認してから変換・前計算する。保存行も、添字・値・行数・末尾まで検査してから配列へ格納する。
- 64以下の素数は18個で、素数配列と成分位置配列の容量20以内。64以下の整数の相異なる素因数は高々3個で、各行の容量8以内。整数ごとの配列添字は0..64である。
- 各成分は高々6ビット、合計は高々42ビット。パックされた部分和は42ビット以内で、全ビットが1の空き番兵とは一致しない。素数冪を作る乗算は、積がN以下になる場合だけ行う。
- ハッシュ表の指数hbは10..MAXHB、従って高々30。表の要素数は2のhb乗で、要素数からバイト数への変換は `SIZE_MAX` を用いて乗算前に検査する。
- リスト容量は2の(hb-2)乗以下で、最大でも2の28乗。倍増の容量検査に使う値も2の29乗以下であり、32ビット以上のlongに収まる。表の充填率は高々1/4なので、空きがなくなって線形探索が回り続けることはない。
- 選択個数と素因数の使用個数は高々63。探索ではxが減少し、2未満を配列参照より前に検査する。深さも高々64段である。
- ハッシュ関数だけは符号なし64ビットの乗算を意図的に剰余計算として使う。Clangでは、この関数の符号なし乗算に限りオーバーフロー診断を除外し、他の整数検査は維持する。

これらは正しい前項だけを使う探索の範囲である。保存値は下記の再検証を通るまで、その前項として利用しない。

## 再開とファイル保護

- `b401472_01.txt` を再開資料とする。読込み前に安定した別ファイル `b401472_01.txt.lock` で排他を取得する。ロックファイルは終了時に削除しない。
- 保存値を探索の上界へ直接代入せず、1から再計算して比較する。指定したNが保存済み範囲より小さい場合はNまでだけ再検証し、保存ファイル全体を保持する。Nより後の最大性を検証したとは扱わない。
- 不正な行、不完全な最終行、誤った保存値を検出した場合は停止する。既存ファイルを勝手に切り詰めたり、誤った行を上書きして修復したりしない。
- 新しい項を証明したら、確定した接頭辞全体を `mkstemp` による固有の一時ファイルへ書く。書込み、フラッシュ、ファイル同期、クローズを確認してから置換する。保存に失敗した項を正常な出力として表示しない。
- 書込みや同期が置換前に失敗した場合、元の結果ファイルを残す。正常な置換の前後でプロセスが終了しても、結果ファイルは新旧いずれかの完全な接頭辞になる。SIGKILL等で残った一時ファイルはGit管理から除外する。
- 結果とロックのシンボリックリンク・複数ハードリンク・通常ファイル以外への操作を拒否する。以前の固定名 `b401472_01.txt.tmp` は使用しない。
- 排他は、このロック規約に従うプログラム間の保護である。規約を無視する旧実行ファイルや外部編集との同時書込みまで保証するものではない。停電・ストレージ故障時のディレクトリエントリーの永続化も保証範囲に含めない。

標準出力は新しく保存できた項の2列データ、進捗・診断は標準エラーへ出す。

警告付きコンパイル・静的解析・サニタイザーの結果は、検査した範囲についての補助的な証拠であり、上の範囲の議論や数学的な根拠を置き換えない。
